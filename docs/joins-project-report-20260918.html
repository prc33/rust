The direct async join is the isolated caller-driven future; its Tokio control includes executor overhead. Rendezvous/condvar have intentionally different wake protocols, and rwlock is an admission probe, not a lock replacement. CFA dumps contain 156 records per mode, 57 reaction bodies, four frontend direct-unary endpoints and four exact zero-bound facts; no general shared matcher fusion is selected.

What is implemented

  • Join syntax still expands through the builtin frontend, while rustc collects typed endpoint/channel/rule descriptors from resolved HIR.
  • MIR calls carry typed JoinCall metadata on the real call terminator; executable operands remain ordinary Rust operands. Legacy marker statements are diagnostic-only and are erased before codegen.
  • Intrabody CFA tracks constructor origins, aliases, escapes, call edges, occupancy facts, closedness and deterministic MIR fingerprints.
  • Result fusion requires a compiler-generated .await ownership path. Helpers, borrows, aggregates, drops, returns, branches, explicit into_future, scopes, competition, cycles and unknown origins are rejected.
  • The paired MIR rewrite validates and changes both constructor and channel call through an exclusive PrivateInstancePlan. The selected endpoint uses Option<DynamicMatcher>; ordinary construction remains available for the guarded nested-dispatch fallback.
  • The fallback preserves the synchronous trampoline’s pending/queued behaviour. No runtime lock implementation was substituted for the protocol, and no custom LLVM pass was added.
  • The runtime fast path records whether nested synchronous work exists, allowing the empty queue pump to be skipped while retaining the active context branch and public fallback.
  • Dynamic one-way emissions use a no-reply admission operation, so a temporary Reply<()> cannot withdraw a queued message before its other pattern inputs arrive.
  • Existing coroutine lowering, polling, pinning, drop elaboration and LLVM lowering continue to handle reaction bodies.

Verification completed

  • Stage-1 compiler and library rebuilt; targeted compiler checks passed.
  • compiler-tests/run_native.sh passed in CFA off, analyze and optimize, with -Zvalidate-mir.
  • Optimised MIR contains both Inner::__join_private_new() and Inner::__join_direct_step(). Off/analyse retain the public constructor/channel calls.
  • Positive owned-payload, owned-output and reentrant scheduling fixtures pass. The multi-input withdrawal fixture and runtime unit tests verify dropped unmatched requests, FIFO removal and independent matched replies. Negative fusion fixtures retain the public path; expected compile-error and panic-transport fixtures behave as designed.
  • The benchmark driver asserts exactly one optimise fusion, none in off/analyse, zero optimise forwarding allocations, and matching checksums.

What remains

  • Shared semantics: demand-gated multi-input matching, atomic claim, multiple independent replies, admission failure, cancellation and execution-owner policy are not compiler-native yet.
  • CFA completeness: analysis is conservative and mostly local. Cross-crate identities, loops, indirect calls, full source rule patterns, generic substitutions, borrowed lifetimes and pass-wide proof invalidation remain open.
  • IR: join operations are typed metadata over ordinary MIR, not yet first-class executable HIR/MIR operations with a complete LowerJoins boundary.
  • Storage: fixed 0/1 queue bounds, stack allocation and atomic/CAS representations have not been proved or selected generally.
  • DataFusion: no production operator coordination has yet been ported to first-class joins, and no DataFusion end-to-end comparison is established.
  • Profiling: static attribution and the first privileged call-graph samples are recorded in the attribution note and raw profile report. The original perf_event_paranoid=4 restriction was lowered to 1 with authorization; samples were collected sequentially with zero lost samples.

Next steps, in order

  1. Use the queue-pump follow-up and committed profile as the baseline for the next lowering; prove execution context before changing the guarded active-dispatch branch.
  2. Keep the new negative coverage for two same-type instances and repeated requests, plus the withdrawal and owned-output regressions. The result and reentrant positives now have isolated JSON rewrite-count assertions; keep this gate on any new positive fixture.
  3. Replace count-only descriptors with complete typed rule/policy records; keep analysis separate from MIR mutation and invalidate certificates at every transforming pass.
  4. Implement conservative CFA for fixed occupancy (especially 0/1), then select inline slots or stack storage only where ownership and lifetime proofs are explicit. Do not pattern-match locks.
  5. Define and lower the shared join protocol, reusing Rust coroutine machinery for reaction bodies and applying thread/lifetime requirements only at actual cross-thread boundaries.
  6. Port a bounded DataFusion coordination path, then run matched native, async and join benchmarks with attribution and regression gates.
